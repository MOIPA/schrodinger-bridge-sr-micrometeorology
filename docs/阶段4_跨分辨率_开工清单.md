## 2. 有卡后的两条命令

```bash
# ① 准备 27 km 粗端数据(纯 CPU,可作为普通作业跑,不占 GPU 队列)
RUN_LSF=1 bash ops/queue/65_phase4_prep.sh              # 默认 DOMAIN=d01
RUN_LSF=1 DOMAIN=d03 bash ops/queue/65_phase4_prep.sh    # 3 km 档

# ② 确认 prep 作业结束后提交训练(GPU)
bash ops/queue/66_phase4_train.sh --arms "p4_27to1_reg p4_3to1_reg"
# 或等 prep 结束自动开跑:
bash ops/queue/66_phase4_train.sh --after <prep作业号>
```

先干跑确认命令长得对:`DRY_RUN=1 FORCE_Q=<队列> bash ops/queue/66_phase4_train.sh`。

## 4. 还没做、需要人盯的

1. **T4.1 的评估**:`84_ensemble_eval.py` 目前按 `p3_arch_*`/`p2_*` 前缀找 ckpt 与重采样配置,
   `p4_*` 需要一份小的适配(粗端域不同 → 读不同的 coarse_dir)。约 1 小时工作量。
2. **T4.2 多档联合输入**:需要在数据集里新增一个 input_group(把 d01/d02/d03 三套粗端拼成通道),
   这是**代码改动**,不是配置改动,建议等 T4.1 两档结果出来再定要不要做。
3. **27 km 的合理性检查**:d01 只有 40×50 量级的格点,插到 1 km 画布后信息量极低,
   第一个 epoch 的 loss 应当明显高于 9 km 档;若反而更低,说明重网格权重或统计量接错了。
