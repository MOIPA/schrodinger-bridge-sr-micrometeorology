# 快照任务说明(2026-10-09 组会汇报配图)

> 给家里 agent 的任务备注。组会报告(组会汇报/2026-10-09/组会汇报-大纲阶段进展.md)已配 9 张统计图,
> 还差一张**个例风场对比图**(真值 vs 粗场 vs 两个模型的实际场)。本任务在服务器导出快照,
> 回传后由本地画图。执行前先 `git pull`。

## 一、任务与执行

```bash
bash ops/queue/65_case_snapshots.sh
```

脚本自动:检查两个 checkpoint → 选兼容队列(PEND=0、排除 P6000)→ 提交 GPU 任务 → 等待并回传。

任务本体是 `scripts/outline/case_snapshots.py`,逻辑:

1. 测试集(myj,144 帧)按 10 m 风速域平均选 **top-3 强风个例**;
2. 对每个个例分别推理 **p2_l1r2_lr2e4**(基线)与 **p3_joint**(联合监督)两个模型;
3. 输出四个来源的场:**truth(d04 真值)、y0(粗端重网格)、pred_base、pred_joint**;
4. 场为 **AGL 100 与 300 m 的 u/v/w**,形状 (n_agl, 99, 120);
5. 存 `results/report_10_09/cases.npz`(压缩,预计 <5 MB)。

## 二、依赖与参照

推理路径完全复用既有代码,不新增任何模型代码:

- `90_agl_eval_phase1.py` 的 `build_si / pad16 / split_denorm`(与评估同口径);
- `agl_eval_common.py` 的 `destagger_canvas / agl_fields / load_tables / load_norm_sigma`;
- 数据集走 `DatasetWindCanvas`(与 `98_phase3_spatial.py` 完全相同的 `build_loader` 设置:全画布 100×121)。

**最近的参照脚本是 `98_phase3_spatial.py`**——本脚本就是把它"累计统计"换成"存场快照"。若运行报错,
先对照 98 的当前实现排查(接口若有变动,以 98/90 为准微调,并回报调整内容)。

## 三、注意事项

1. **只跑 myj**(默认 `config.data.scheme` 已是 myj),两套方案的标签不同,不要混;
2. 快照推理用 `add_noise=False`(确定性采样),与评估一致,保证可复现;
3. 预计总耗时 <15 分钟(读 144 帧 + 6 次推理),无需训练预算;
4. 若队列繁忙导致 PEND,脚本已带一次重选;仍失败则手动换队列重投;
5. 回传内容:日志 `ops/result/65_case_snapshots.txt` + `results/report_10_09/cases.npz`。

## 四、验收

- `cases.npz` 存在,`du -h` 显示非空;
- 日志尾部打印了 3 个 case 的 `idx / stamp / metric` 与"已保存"行;
- npz 键结构:`case{k}_{src}_{u|v|w}`(src ∈ truth/y0/pred_base/pred_joint),
  以及 `case{k}_stamp`、`agl`。

生成个例四联图(真值 / 粗场 / 基线 / 联合监督),插入报告。若 npz 结构与上述不符,
本地按实际结构微调绘图函数即可。
