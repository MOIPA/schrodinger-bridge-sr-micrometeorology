# 外传-4 · 级联超分与跨尺度迁移(定稿)

> 数据日期:2026-11-03。口径:144 h 测试集(**2020-07-16T00–2020-07-31T23**),主指标 = AGL 10–500 m 九层平均风矢量 RMSE(池化),与阶段 3 / 阶段 4 完全一致。
> 全部数字来自 `sidequest_scale3x/results/*_perhour.npz` 与 `results/phase4/p4_27to1_reg_perhour.npz`,由 `cmp_casc.py` / `xfer_retention.py` 统一重算(块 24 h、2000 次配对 bootstrap)。
> 本文取代 `外传-4_级联与迁移_草稿.md`(草稿中的 `⟨TODO⟩` 与早期数字一律作废)。

## 0 一句话

**三步级联(27→9→3→1)与一步直连(27→1)打平**(1.0588 vs 1.0909,Δ=−0.0321,CI [−0.0652, +0.0026] 跨 0);**零样本跨尺度迁移只保住 29–39% 的相对增益**,说明超分算子尺度专用性强;三档增益 27→9 (+40.9%) > 9→3 (+37.4%) > 3→1 (+26.2%) 在统一划分下成立。

## 1 这段在回答什么问题

老师那句"每个阶段灰度区间不一样"拆成三个可检验的问题:

1. **起点越粗是不是越难?** —— 三档同跨度(3×)对比,见 §3 与 `外传-3b`。
2. **一步跨 9 倍 vs 分三步各跨 3 倍,哪个更准?** —— 级联 vs 直连,§4–§5。
3. **一个尺度学到的映射搬到别的尺度还能用吗?** —— 交叉迁移,§6。

问题 2、3 只做推理,不训新模型(直连那一臂即阶段 4 的 `p4_27to1_reg`)。

## 2 前置坑:三档的划分原本不一致(已修)

`synth_coarse.py` 组装第二级粗端时暴露出:第一级 dump 的测试时次是 07-01–07-13,第二级要的是 07-16–07-31。`ops/debug/check_splits.py` 实测交集(修复前):

| 对比 | train | valid | test |
|---|---|---|---|
| sq9to3 vs sq27to9 | 408 / 528 | 0 / 72 | 0 / 144 |
| sq3to1 vs sq27to9 | 408 / 528 | 0 / 72 | 96 / 144 |
| 阶段3 vs sq27to9 | 432 / 528 | 0 / 72 | 0 / 144 |

根因:`scripts/outline/30_blocks_and_split.py` 用**本尺度自己的粗端**算 `ws_low / ust / pblh / hfx / unstable_frac` 再做一维最优分段,块边界随尺度不同 → 划分必然不同。

处置:三档统一到阶段 3 的 `split.json`(`prep_stats.sh` 的 `FORCE_SPLIT_FROM=`),强制重算标准化;修复后四套 split **完全一致**(train 528 / valid 72 / test 144)。

### 2.1 由此引发的第二次泄漏(必须记录)

统一划分后重训时,训练脚本发现既有 `checkpoint.pth` 就 **full resume**,而旧权重是在旧划分上训的(旧 train 含新 test 时次) → 等于测试期泄漏。

- 发现方式:重训启动 5 分钟就显示 `Epoch 46`;
- 处置:`prep_stats.sh` 在 `FORCE_SPLIT_FROM` 分支里自动把旧 ckpt 移到 `data/DL_result/_old_split/`;
- 漏网一个:`sq9to3_reg` 重训跑完并打印 `Train end`,但 **best 权重没被重写**(验证损失没超过旧模型),评估读到的仍是旧划分的模型。证据两条:① ckpt mtime 11-01 23:08,比 `Train end`(18:24 UTC = 02:24 本地)早 3 小时;② 其 RMSE 与旧划分逐位相同(0.5071)。隔离后重训(best epoch 96),干净值为 **0.4943**。
- 教训:**"训练完成"不等于"权重是这次训的"**。日志与队列都只能证明进程跑完,只有 ckpt 的 mtime(配合 `ops/debug/leak_check.py` 与 split 的 mtime 比较)能证明模型身份。

### 2.5 真粗端缺口(级联的"预期"从哪来)

`外传-1b` 用真粗端 + 项目自己的重网格权重量了四对(6 时次 × 最低 23 模式层):

| 尺度段 | R² | 缺口方差占比 |
|---|---|---|
| 27→9 | 0.974 | 2.6% |
| 9→3 | 0.796 | 20.4% |
| 3→1 | 0.842 | 15.8% |
| 27→1 | 0.443 | 55.7% |

配准已用循环平移核对(平移一律使相关下降,见 `ops/debug/gap_check.py`)。9→3 存在**该域特异的 +0.316 m/s 偏差**(细端比粗端强),成因指向域覆盖差异,未分离,只记录。

## 3 三档同跨度对比(统一划分、干净权重)

| 尺度段 | 主 RMSE | y0(插值基线) | 相对增益 | best epoch |
|---|---|---|---|---|
| 27→9 | 0.6142 | 1.0395 | **+40.9%** | 45 |
| 9→3 | 0.4943 | 0.7902 | **+37.4%** | 96 |
| 3→1 | 0.4748 | 0.6433 | **+26.2%** | 123 |

排序 27→9 > 9→3 > 3→1,首尾差 **14.7 pp**。按 `外传-3b` §3 预登记,这落在第 ① 条(排序不变 → 原结论成立)。⚠️ 绝对 RMSE 跨尺度不可比(y0 本身在变),只能比相对增益。

## 4 级联设计:只许用 27 km 的信息

要跟"一步 27→1"公平比,整条链**不许偷看中间尺度的真值**:

1. 第 1 级 `sq27to9_reg`:粗端 = 真 d01(27 km),输出 9 km 场;`84 --dump_fields` 把逐时次 u/v/w **原生交错**物理场写到 `d_<stamp>.npz`;
2. `synth_coarse.py` 把这些预测填进下一级粗端 npz 的 `c_u[levels]/c_v/c_w[wl]`;8 个 2D 地面场(`c_rmol c_ust c_pblh c_hfx c_t2 c_psfc c_coszen c_coszen_wrf`)**从上一级粗端重网格带下来**,而不是取真值;
3. 第 2 级 `sq9to3_casc` → 同法 → 第 3 级 `sq3to1_casc`。

判据边界(`外传-4_草稿` §3.1 预登记,数字按定稿更新):**上界 0.4748**(3→1 喂真 3 km 粗端),**对手 1.0909**(一步直连)。X < 0.4548 视为泄漏先查;0.4748 ≤ X ≤ 1.0909 → 分步不亏;X > 1.0909 → 分步更差。

## 5 级联结果

| tag | 主 RMSE | y0 | Δ vs 一步直连 | 95% CI | 判定 |
|---|---|---|---|---|---|
| `p4_27to1_reg`(一步 27→1) | 1.0909 | 1.5168 | 0 | — | 对手 |
| **`sq3to1_casc_casc`(级联终点)** | **1.0588** | 1.0966 | **−0.0321** | **[−0.0652, +0.0026]** | **跨 0,不显著** |
| `sq9to3_casc_casc`(第 2 级) | 0.7948 | 0.9778 | −0.2961 | [−0.3513, −0.2682] | — |
| `sq27to9_reg_casc`(第 1 级) | 0.6142 | 1.0395 | −0.4767 | — | 与域内一致 |

自洽守卫:`sq27to9_reg_casc` 与 `sq27to9_reg` 的 **Δ = 0.00e+00** ✅(第 1 级粗端本就是真 d01,两者必须数值同一)。

**判读(按预登记)**:CI 跨 0 → 只能说 **"分三步没有额外损失",不能说更准**。级联终点 1.0588 距上界 0.4748 很远,距直连 1.0909 很近 —— **瓶颈是"27 km 里到底有多少 1 km 信息",不是"一步跨 9 倍太难"**。

> 更正记录:早前版本用**泄漏的 9→3 权重**算出 1.0517 / CI [−0.0715, −0.0069],曾判为"显著更优"。干净权重下为 1.0588 / CI [−0.0652, +0.0026],**原判断作废**。

## 6 交叉迁移(零样本)

把 A 尺度训的权重直接拿去评 B 尺度(数据/统计量/划分全用 B 侧,只换 checkpoint):

| 迁移 | 迁移 RMSE | 域内 RMSE | 迁移增益 | 域内增益 | 增益保持率 |
|---|---|---|---|---|---|
| 27→9 权重 → 9→3 任务 | 0.6750 | 0.4943 | +14.6% | +37.4% | **39%** |
| 3→1 权重 → 27→9 任务 | 0.9160 | 0.6142 | +11.9% | +40.9% | **29%** |

→ **算子尺度专用性强**:换尺度零样本部署会丢掉 61–71% 的相对增益,但仍**显著优于插值**(保住的 12–15% 是真的)。`retained` 不是准确率保持率,两个数都要写。

## 7 能下与不能下

**能下**

1. 三档增益排序 27→9 > 9→3 > 3→1,统一划分下成立,首尾差 14.7 pp。
2. 三步级联 ≈ 一步直连(差 3%,不显著):细分不亏,也无额外收益。
3. 级联的瓶颈是粗端信息量(距上界 0.4748 差 0.58),不是跨度。
4. 零样本跨尺度只保住 29–39% 增益 → 尺度专用性成立。

**不能下**

1. 不能说"27 km 信息足够重建 1 km"——直连 1.0909、级联 1.0588 都远高于 3→1 的 0.4748。
2. 不能把级联终点与三档自训排名混为一谈(粗端信息量不同,那一列是**标价**)。
3. 不能从零样本保持率反推"尺度不变性";也不能说"某个尺度更好训"——绝对 RMSE 不可跨尺度直比。
4. 9→3 的 +0.316 m/s 偏差成因未分离,不许当"9 km 风场偏强"的物理事实。

## 8 工程记录

1. **split 不一致**(§2):必须统一,否则级联跑不通、三档数字不可比。
2. **full-resume 泄漏**(§2.1):旧 ckpt 必须隔离;`prep_stats.sh` 已自动处理,`leak_check.py` 可体检。
3. **日志被覆盖会毁掉审计证据**:重复续训用 `>` 重定向,`Train end` 行会消失。已给 `eval3.sh`/`cascade.sh` 的闸门加 `SKIP_TRAIN_GATE=1` 逃生口,**放行时打印 ckpt 的 mtime 与字节数**供人工核对。
4. **闸门环境变量要透传**:外层 `eval3.sh` 拿 `SKIP_TRAIN_GATE` 判"是否提交",内层 bsub 作业的命令串若不带该变量,内层照样被拦(表现为 1.4 s "Done successfully")。
5. **`-w ended(<jobid>)` 会假满足**:作业被抢占换号、旧号离开历史后依赖立即满足,拿半成品权重评估。已有两道闸门,且 `cascade.sh` 每级后校验产物存在。
6. **`ln -sfn` 目标是真实目录时软链建在目录内部**:`cascade.sh` 的 `link_ckpt()` 检测到非软链即 `exit 1`。
7. **tqdm 读数**:`[1/151 … 291s/it]` 里 151 是总轮数、s/it 是秒/轮。
8. **地面场来源错配**:第 3 级的 2D 场必须取自第 2 级输出目录;喂错会报 `cannot reshape array of size 27000 into shape (18000,)`,已在 `synth_coarse.py` 加前置守卫(比**源**网格而非目标网格)。

## 9 复现命令

```bash
# 1) 统一划分 + 重算统计量(split 以阶段3为准)
FORCE_SPLIT_FROM=prepare_npz_outline_static/split.json \
  bash sidequest_scale3x/queue/prep_stats.sh

# 2) 三档训练(各自独立,4–6 h/档)
FORCE_Q=<队列> TAGS="sq27to9_reg sq9to3_reg sq3to1_reg" \
  bash sidequest_scale3x/queue/train3.sh

# 3) 域内评估
FORCE_Q=<队列> TAGS="sq27to9_reg sq9to3_reg sq3to1_reg" \
  bash sidequest_scale3x/queue/eval3.sh

# 4) 级联三级(需 GPU,约 25–40 min)
bsub -q <队列> -gpu "num=1" -n 4 -R "rusage[mem=32000]" \
  -J casc bash -lc "cd \$PWD && bash sidequest_scale3x/queue/cascade.sh"

# 5) 对照表 + 迁移保持率
python sidequest_scale3x/scripts/cmp_casc.py \
  --dir sidequest_scale3x/results,results/phase4 --ref p4_27to1_reg \
  --tags p4_27to1_reg,sq3to1_casc_casc,sq3to1_reg,sq9to3_casc_casc,sq9to3_reg,sq27to9_reg_casc,sq27to9_reg \
  --block 24 --n_boot 2000
python sidequest_scale3x/scripts/xfer_retention.py --dir sidequest_scale3x/results \
  --pairs xfer9to3_by27to9_reg:sq9to3_reg,xfer27to9_by3to1_reg:sq27to9_reg
```
