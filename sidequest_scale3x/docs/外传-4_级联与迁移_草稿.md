## 1 这段在回答什么问题

老师那句"每个阶段灰度区间不一样"可以拆成三个可检验的问题:

1. **同样是放大 3 倍,起点越粗是不是越难?**(外传-3 在做,数字待重出)
2. **一步跨 9 倍(27→1)和分三步各跨 3 倍(27→9→3→1),哪个更准?** —— 这是"级联 vs 直连"。
3. **一个尺度学到的映射,搬到别的尺度还能用吗?** —— 这是"交叉迁移"。

问题 2、3 都只需要推理,不训新模型(除了已经在训的一步 27→1 直连),所以先做。

### 2.5 真粗端缺口(级联的"预期"从哪来)

`外传-1b_真粗端的缺口.md` 用真粗端 + 项目自己的重网格权重量了四对:

| 尺度段 | R² | 缺口方差占比 | σ细/σ粗 | 残差 RMSE |
|---|---|---|---|---|
| 27→9 | 0.974 | 2.6% | 1.025 | 0.671 |
| 9→3 | 0.796 | 20.4% | 1.130 | 0.920 |
| 3→1 | 0.842 | 15.8% | 1.070 | 0.460 |
| 27→1 | 0.443 | 55.7% | 1.652 | 0.844 |

对级联实验的两个用处:

1. **预期方向**:级联每级的缺口都比"一步 27→1"小得多(2.6%/20.4%/15.8% vs 55.7%),所以级联**有机会**不输给直连;
2. **预期代价**:第 2 级(9→3)是缺口最大的一档,而且真粗端在那一档整体偏强 **+0.316 m/s** —— 级联的误差很可能就是在这里被放大。这给了"如果级联变差,差在哪"一个可检验的先验。

> ⚠️ 这条先验只用于**解释**结果,不用于**判定**。判定仍按 §6 的预登记规则(只看配对块 bootstrap 的 CI 是否跨 0)。

## 3 级联怎么接(27→9→3→1)

设计约束:**整条链只允许用 27 km 的信息**,否则和"一步 27→1"比就不公平。

- 第 1 级 `sq27to9`:粗端 = d01(27 km)真实场 → 输出 9 km 风场。
- 第 2 级 `sq9to3`:粗端**风场换成第 1 级的预测**(`synth_coarse.py` 写进 `c_u/c_v/c_w` 的对应层);
  地面 2D 场(`c_rmol/c_ust/c_pblh/c_hfx/c_t2/c_psfc/c_coszen/c_coszen_wrf`)从**第 1 级的粗端(d01)**重网格过来,不允许直接抄 d02 真值。
- 第 3 级 `sq3to1`:同上,粗端风场用第 2 级输出,2D 场继续从 d01 带下来。

所以级联的误差会**逐级累积**,但每一级看到的都是"上一级真会给它的东西"。

> ⚠️ 已知的一个具体风险(来自 `外传-1b §5.1`):9→3 这一档的**真粗端在子域内系统性偏弱 ~5%**
> (平均 bias +0.386 m/s,峰在急流层),模型因此学到「放大 ~5%」。注意这条**不是** 3× 平滑的普遍规律
> ——同为 3× 的 27→9 只有 +0.038,成因仍指向域覆盖/地形代表性。
>
> 级联里第 2 级的输入是第 1 级的**预测**,而预测又来自 27 km 端,所以这一档的「放大」可能过头。
> 判据:看 `casc_stages.py` 逐级表里第 2 级的**风速偏差**(不只是 RMSE)。若明显偏离 0,
> 级联终点的高层误差就多了一层「增益失控」的解释,而不是笼统说「误差逐级累积」。

## 4 交叉迁移怎么测

零样本:数据/静态场/标准化**全部用目标尺度**的,只把 checkpoint 换成源尺度训出来的权重。

- `xfer9to3_by27to9_reg`:27→9 的权重去干 9→3 的活
- `xfer27to9_by3to1_reg`:3→1 的权重去干 27→9 的活

判读方式:相对插值增益能保住原任务的百分之多少。

### 5.0 已经到位的锚点:一步 27→1 直连(11-01 21:15)

级联的比较对象先落地了,详见 `docs/阶段报告/阶段4a_一步27to1_首评.md`:

| 项 | 值 |
|---|---|
| 主指标 RMSE(AGL 10–500 m) | **1.0909** |
| 插值基线 y0 | 1.5168 |
| 相对插值增益 | **+28.1%** |
| 切变 RMSE | 0.00914 |
| 训练 | 14833575,Best epoch 23,best_loss 0.16139847,第 63 轮早停 |
| 逐日 RMSE | 07-16 0.8870 / 07-17 0.8968 / 07-18 0.8968 / 07-19 0.9668 / 07-30 1.4110 / 07-31 1.3489 |
| 逐日相对增益 | +42.3% / +41.2% / +44.0% / +36.2% / **+6.1%** / **+4.4%** |

两条对级联有直接影响的事实:

1. **直连在强风日几乎没用**(+4.4% / +6.1%)。如果级联能把这两天拉回来,那才是它真正的价值;
   若只是在平静日再挤出一点,哪怕均值 Δ 显著,也不值得写成一节。
2. 直连的**绝对**误差在 1.09 m/s 量级,而用真 3 km 粗端自训的 sq3to1 在旧口径下是 0.44 —— 中间差了
   一倍多。级联的终点如果落在 0.6–0.7 之间,说明"分三步"确实把 27→1 的 9 倍跨度摊薄了;
   如果停在 1.0 以上,说明误差主要不是"跨度太大",而是"27 km 的信息就这么多"。

## 6 能下与不能下

本节是**事先写好的判定规则**:结果出来之前就定好"什么数对应什么话",免得看到数字再挑措辞。

### 6.1 判定规则(先定后看)

| 级联终点 vs 一步 27→1 直连 | 写法 |
|---|---|
| Δ 的 95% CI 完全在 0 以下 | "在这一批 144 h 上,分三步走反而比一步到位更准"——此时要追问原因(中间尺度的归纳偏置是否起了正则作用),不能只报数字 |
| CI 跨 0 | "两者分不出来"——只能写"级联没有额外损失",**不能**写"级联更好" |
| CI 完全在 0 以上 | "级联有明确代价",并给出代价的量化(Δ 与相对插值增益的差) |

### 6.2 无论结果如何都成立的

- 级联与直连**信息量对等**是本实验的前提:整条链只用 27 km 的风场与地面场,中间尺度的真值一次都没进过模型(2D 场由 27 km 重网格带下来,见 §3)。这条保证了比较不是"谁偷看了更多"。
- 三档的**划分已统一**(test 2020-07-16T00–07-31T23,144 h),所以三档之间、级联与直连之间的差异不再是"天气期不同"造成的;统一前的旧数字(外传-3 初版、早期迁移数)一律作废。
- 交叉迁移是**零样本**:模型没见过目标尺度的任何样本,也没微调。它衡量的是"同一张映射在不同基尺度之间能搬多远",不等于"迁移学习能做到什么"。

### 6.3 不能说的

- 不能说"27 km 的信息足够重建 1 km"——级联只是把 27 km 的信息分三次用完,终点误差仍可能明显高于用真 3 km 粗端自训的 3→1(那一行就是代价的度量)。
  代价的锚已经可以给出:直连 27→1 是 1.0909,而真 3 km 粗端自训的 3→1 在旧口径下是 0.4390(待重训后更新)。级联夹在这两者之间。
- 不能把级联终点与三档各自的自训结果直接比"谁更好":它们用的粗端信息量本来就不同(27 km vs 9 km vs 3 km),这一列的用途是**标价**,不是排名。
- 不能从零样本迁移的百分比反推"尺度不变性":三个尺度上残差的谱斜率相近(`外传-1`)只说明粗糙度自相似,不说明映射可移植;而真粗端的缺口比例三段是 2.6%/20.4%/15.8%,连"缺口单调"都不成立(`外传-1b`)。

## 7.0 CPU 冒烟抓到的一个真 bug(2026-11-01 19:47)

真跑之前用 `ops/debug/cascade_cpu_smoke.sh`(独立 tag、只读旧权重、1 帧、纯 CPU)把
"dump → synth → 生成配置 → 二级推理"走了一遍。第一轮直接失败,报的却是这句:

```
--td_from 的 2D 场有 27000 个格点((150, 180)),而 --td_statics 的源网格是 (120, 150)
```

而 `--td_from prepare_npz_outline_coarse_d01 --td_statics prepare_npz_outline_static_sq27to9`
**这个调用本身是对的**:d01(150×180)正是 sq27to9 这组重网格权重的**源网格**,目标是 d02(120×150)。
错在我上一轮写的守卫拿 `stat.fine_shapes['mass']`(目标网格)去比了源网格 —— 把合法调用判成错误。
若没冒烟,这个 bug 会在 GPU 队列上排到凌晨才暴露,而且报错信息会把人引向"数据坏了"的错误方向。

修法(commit):守卫改比 `stat.d['regrid_shape_mass']`(源网格);真正的错配(d01 的场喂给 d02→d03 的权重)
仍然会被拦住。

冒烟最终通过:`[cpu-smoke] 通过:dump → synth → cfg → 二级推理 全链路无异常`,
第 1 级 1 帧 RMSE 0.4702、第 2 级 0.5867(1 帧、旧权重,数字无意义,只证明链路通)。

## 7 工程记录

- `84_ensemble_eval.py --dump_fields` 没建目录就写盘 → `FileNotFoundError`;已加 `os.makedirs`。
- 级联里 checkpoint 软链写成 `../某目录`,在 `$CK` 内部解析会多退一层 → 84 打印"缺 checkpoint"但**仍然 exit 0**,`set -e` 拦不住;已改同级目录名 + 每级产出检查。
- 登录节点 `rm -rf /tmp/casc` 删不到计算节点的 `/tmp`(两套文件系统)。
- 训练日志 `logs/<tag>_<jobid>.out` 是 LSF 的 `-o`,**作业结束才落盘**;想看实时进度要去 `logs/<tag>.log`(训练脚本自己写的那个),别把空文件当卡死。
- **级联组装最容易错的一处**:第 3 级(→3 km)的地面场必须来自第 2 级的输出目录 `prepare_npz_outline_coarse_casc_s2`,不是更粗的 `..._coarse_d01`。喂错时报的是 `ValueError: cannot reshape array of size 27000 into shape (18000,)`(27000=150×180 是 d01 质量点,18000=120×150 是 d02 的),完全看不出病因;已在 `synth_coarse.py` 里加网格守卫,提前比对 `--td_from` 的 2D 场格点数与 `--td_statics` 的源网格,直接报"这一级的地面场应该来自上一级输出目录"。
- **级联先做 CPU 预检再上 GPU**:`ops/debug/cascade_smoke.py` 用真实粗端模板造一个假的上一级预测,走一遍 `synth_coarse.py`,逐项核对输出键、风场形状、写入层值、2D 场有限性。两级(→9 km、→3 km)均已通过,这才把 GPU 时间花在推理上而不是试错上。

- **统一划分后重训时,训练脚本会自动 `full resume`**——只要 `data/DL_result/.../config_wind_canvas_<tag>/checkpoint.pth`
  存在就续训。旧权重是在旧划分上训的,而旧划分的训练集包含统一后的**测试期时次**,续训等于把测试期泄漏进模型。
  发现方式:重训作业跑了 5 分钟日志就显示 `Epoch 46`(一个 epoch 要 4 分钟,不可能)。处置:先 `bkill` 下游依赖作业,
  把旧权重目录移到 `data/DL_result/_old_split/<tag>_preunify`,重投后确认 `Epoch 1`;并在 `prep_stats.sh` 的
  `FORCE_SPLIT_FROM` 分支里**自动**把对应 checkpoint 目录移走,防止下次再犯。这条是本项目目前为止
  最接近"静默污染结果"的一次事故,幸好被 epoch 数对不上抓住。

- **下游作业别只靠 `-w ended(<jobid>)` 兜底**。作业被抢占/重投后作业号会变,旧作业号从 LSF 历史里掉出去时
  `ended()` 的判定并不可靠 —— 一旦提前满足,评估与级联会拿**半成品 checkpoint** 跑完,并把假数 commit 进仓库
  (11-01 就发生过一次评估作业没挂上依赖、立刻 RUN)。现在 `eval3.sh` 与 `cascade.sh` 都加了一道**内容闸门**:
  `grep -qa "Train end" logs/<tag>.log`,没有就 `[skip]` / 中止。内容闸门比作业状态可靠 —— 作业被杀、被抢占、
  掉进 `lost_and_found`,`Train end` 都不会凭空出现。另配有 `ops/debug/leak_check.py`,用"checkpoint 的 mtime
  是否早于 split.json"体检"旧划分权重续训"的风险(只作提示,不作断言)。
- **tqdm 的读法**:`[1/151 ... 270.92s/it]` 里 151 是**总轮数**、`s/it` 是**秒/轮**,不是"每轮多少个 batch"。
  我曾按错读法判断"机器慢了一百倍"。另外 bar 每轮重置但累计计时不重置,`[03:31<…]` 是累计时间。
- **`INNER=0` 不等于"外层提交"**:脚本写的是 `if [ -z "${INNER:-}" ]`,判的是"空",所以 `INNER=0` 会走
  **登录节点直接跑**的分支,报 `RuntimeError: Found no NVIDIA driver on your system`。正确用法是不设 `INNER`。
- **bsub 输出丢进 `/dev/null` 时,"提交失败"和"提交成功"在日志里长得一样**:守护脚本曾打了"已接管"日志却
  没有任何作业入队。改为解析 `is submitted` 并回显 `Job <id>`,提交失败才看得见。
- **checkpoint 软链守卫**:`ln -sfn` 的目标若已存在且是**真实目录**,软链会被建到那个目录**内部**
  (我因此一度把冒烟作业指向了正在训练的 checkpoint)。`cascade.sh` 已加 `link_ckpt`:真实目录直接报错退出。
