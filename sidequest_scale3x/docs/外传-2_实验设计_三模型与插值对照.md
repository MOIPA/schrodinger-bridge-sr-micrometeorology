## 1. 先确认我们理解的是不是同一件事

老师原话是"比较 27-9、9-3、3-1 的超分模型的区别,因为每个阶段的灰度区间不一样"。这句话至少有三种读法:

| 读法 | 含义 | 我们要跑的东西 |
|---|---|---|
| **A. 分辨率跨度(我们采用)** | 三段都是 3 倍,只是起点不同:27→9、9→3、3→1 | 三个同架构模型 + 各自对插值的增益 |
| B. 值域/动态范围 | 不同分辨率下风场本身的取值范围不同,标准化口径要分别做 | 每段单独统计 normalize(已做) |
| C. 可预测性 | 缺口方差占比不同(4.2% / 7.3% / 11.3%) | 外传-1 已量化 |

**A 和 B 在我们这儿是同一件事的两面**:三段都是 3×,唯一变化的是起始分辨率,所以"灰度区间"的差异可以直接用统计量描述(外传-1 的 R²、σ_f/σ_c、残差峰度、谱斜率),不必另立一套数据。

## 2. 三个模型 + 一条插值基线

```
d01 (27 km) ──插入──► d02 (9 km)   → sq27to9_reg
d02 ( 9 km) ──插入──► d03 (3 km)   → sq9to3_reg
d03 ( 3 km) ──插入──► d04 (1 km)   → sq3to1_reg
```

- **架构完全相同**(与阶段 3 的 `p3_arch_reg` 逐键一致,79.26M UNet 回归),只换数据;
- **插值基线 y0**:粗端场按重网格权重放到细网格上——这就是"普通插值法",数据集自带,评估脚本直接输出它的 RMSE;
- **增益** = 1 − RMSE_模型 / RMSE_插值,同口径(AGL 10–500 m 池化、144 h 测试块)。

主产出表(训练完自动生成 `sidequest_scale3x/results/summary3.md`):

| 模型 | 主指标 RMSE | 插值 y0 RMSE | 相对插值增益 | 切变 RMSE |
|---|---|---|---|---|
| sq27to9_reg | | | | |
| sq9to3_reg | | | | |
| sq3to1_reg | | | | |

**这张表就是老师要的"区别"**:增益随起点分辨率怎么变——是单调下降(越粗越难)、还是有个拐点。

## 3. 另外两个更硬的问题(建议一并回答)

老师问"区别",但真正能说明"每个阶段不一样"的是下面两个对照:

### 3.1 交叉迁移:模型是"学会了超分"还是"记住了这个尺度"

把 3→1 训好的权重直接拿去评 27→9(d02 画布),误差会炸成什么样;

- 如果炸得很惨 → 说明学到的是**特定尺度的纹理**,不是通用的超分算子;
- 如果还能用 → 说明三段共享一个算子,那就应该训一个模型通吃(这对论文是很强的卖点)。

实现:84 评估脚本按 config 建数据集,换个 `--cfg_root` 指向另一组的配置 + `--ck_root` 指向这组的 checkpoint 即可,不需要改代码。

### 3.2 级联 vs 直连:27→9→3→1 串起来,能不能打过一步 27→1

- 直连:阶段 4 的 `p4_27to1_reg`(9×,一次跳);
- 级联:sq27to9 → sq9to3 → sq3to1 首尾相接。

这条对照能回答"超分应该一步到位还是逐级放大",是审稿人一定会问的工程问题。

## 4. 与阶段 4 的关系(别重复劳动)

阶段 4 原计划两档:**27→1(9×)** 与 **3→1(3×)**。

其中 **3→1 与外传的 sq3to1 是同一个实验**,只是配置目录不同。所以:

- 阶段 4 只保留 **27→1** 这一档(它是唯一真正的 9× 任务);
- **3→1 直接复用 sq3to1_reg 的权重与结果**,配置不再重复训练;
- 这样阶段 4 的 GPU 预算从 ~35 卡时降到 ~25 卡时。
