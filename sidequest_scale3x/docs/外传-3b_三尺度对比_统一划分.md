# 外传-3b · 三尺度同跨度对比(统一划分版)

> 数据日期:2026-11-03。口径:144 h 测试集(**2020-07-16T00–2020-07-31T23**,统一划分),主指标 = AGL 10–500 m 九层平均风矢量 RMSE(池化),与阶段 3 / 阶段 4 / 外传-4 完全一致。
> 本文是 `外传-3_三尺度对比_定稿.md` 的**重做版**:那一版的三档用了各自的 `split.json`,测试时次交集为 0,数字不可比(已作废)。本文数字全部来自统一划分下重训的权重。
> 预登记结论写在 §3,先于结果定好判据(2026-11-01 写,2026-11-03 复算)。

## 0 一句话

同样放大 3 倍,**起点越粗越容易**——相对插值的增益 27→9 **+40.9%** > 9→3 **+37.4%** > 3→1 **+26.2%**,首尾差 **14.7 pp**,落在预登记"排序不变"的分支。

## 1 为什么重做

第一轮三档各自的 `split.json` 是用**本尺度自己的粗端**做天气分块(`30_blocks_and_split.py` 的 `daily_indicators`)得到的,块边界随尺度不同,导致:

| 对比 | valid 交集 | test 交集 |
|---|---|---|
| sq9to3 vs sq27to9 | 0 / 72 | **0 / 144** |
| sq3to1 vs sq27to9 | 0 / 72 | 96 / 144 |
| 阶段3 vs sq27to9 | 0 / 72 | 0 / 144 |

三档在比**三个不同的天气期**,数字没有可比性;而且级联根本跑不通(第 1 级 dump 的时次不是第 2 级要的)。

处置:三档统一到阶段 3 的 `split.json`(`prep_stats.sh` 的 `FORCE_SPLIT_FROM=`),强制重算标准化,并把旧划分权重移到 `data/DL_result/_old_split/`(否则训练脚本 `full resume` = 测试期泄漏)。

## 2 方法

- 三档配置除 `data.coarse_dir / statics_dir / split_manifest / normalize_json / hr_data_shape / dl_data_ver` 外与阶段 3 基座**逐键相同**(76.26M 参数同架构、同损失、同训练轮数上限);
- 粗端:27→9 用 d01(27 km)、9→3 用 d02(9 km)、3→1 用 d03(3 km);细端:d02 / d03 / d04;
- 指标:与阶段 3 同一套 AGL 算子(11 层 10–1000 m),主指标取 ≤500 m 九层池化;插值基线 y0 由 `acc_y0` 同一口径算出;
- 显著性:块长 24 h、2000 次配对移动块 bootstrap(`cmp_casc.py`,与 99b 同实现)。

## 3 预登记判据(先定后看)

| 情形 | 允许写什么 |
|---|---|
| ① 排序 27→9 > 9→3 > 3→1 | 原结论成立(须注明是**相对插值**口径) |
| ② 排序变化 | 原结论被推翻,只能写"关系在本月数据上不稳定" |
| ③ 首尾差 < 3 pp | 只能写"三档相近",不许画下降曲线 |
| ④ 任何情形 | 不许再用块平均代理口径的 4.3 / 7.7 / 10.4% 当横轴(已被真粗端 2.6 / 20.4 / 15.8% 取代且排序不同) |

## 4 结果

| 尺度段 | 主 RMSE | y0 | 相对增益 | best epoch | best_loss |
|---|---|---|---|---|---|
| 27→9 | 0.6142 | 1.0395 | **+40.9%** | 45 | 0.13511 |
| 9→3 | 0.4943 | 0.7902 | **+37.4%** | 96 | 0.11663 |
| 3→1 | 0.4748 | 0.6433 | **+26.2%** | 123 | 0.08612 |

→ 命中情形 ①:**排序不变,首尾差 14.7 pp ≫ 3 pp**,原结论在统一划分下成立。

三条辅助观察:

1. **绝对误差递减(0.61 → 0.49 → 0.47)但难度递增**:y0 也在递减(1.04 → 0.79 → 0.64),所以"绝对 RMSE 更小"不代表更容易,只有相对增益可比。
2. **起点越粗,best epoch 越早**(45 / 96 / 123):粗端信息少 → 模型更快到平台,而 3→1 需要更多轮才收敛。
3. **与真粗端缺口不完全单调**:R² 是 0.974 / 0.796 / 0.842、缺口方差占比 2.6% / 20.4% / 15.8%(9→3 的缺口**比** 3→1 大),但相对增益仍是单调的 —— 说明"缺口大小"不是难度的唯一决定因素,还取决于缺口的**可预测性**(9→3 那对域存在 +0.316 m/s 的系统偏差,见 `外传-1b` §5.1)。

## 5 能下与不能下

**能下**

1. 三档同跨度(3×)对比中,相对插值增益随基尺度变细而单调下降,幅度 40.9% / 37.4% / 26.2%。
2. 该结论在"统一划分 + 干净权重"下复现,不是划分造成的假象。

**不能下**

1. 不能说"27→9 模型比 3→1 模型好"——两者任务不同,绝对 RMSE 不可跨尺度直比。
2. 不能把 9→3 的缺口偏大当成"9 km 最难";它的缺口比 3→1 大但增益比 3→1 高。
3. 不能外推到"任意尺度";本结论覆盖 27 / 9 / 3 / 1 km 四档、一个月样本。
4. 不能用块平均代理口径的缺口数字做横轴(见 §3 情形 ④)。

## 6 工程记录

1. **划分决定可比性**:三档必须先统一 `split.json`,否则一切对比无效(第一轮就是这样废掉的)。
2. **重训时的隐性泄漏**:训练脚本见 checkpoint 即 `full resume`,旧划分权重会把测试期样本带进训练。已在 `prep_stats.sh` 自动隔离。
3. **`Train end` 不等于权重是这次的**(`sq9to3_reg` 实例):重训跑完但验证损失没超过旧模型 → best 权重没被重写,评估读到旧模型。靠 ckpt mtime 与 split mtime 比较(`ops/debug/leak_check.py`)+ RMSE 与旧划分逐位相同两条独立证据抓出;隔离重训后 0.4943(best epoch 96)。
4. **统一划分后的标准化必须重算**(`normalize_config.json` 删掉让 `40_stats.py` 重跑),否则统计量仍来自旧训练块。

```bash
  --dir sidequest_scale3x/results --ref sq27to9_reg \
  --tags sq27to9_reg,sq9to3_reg,sq3to1_reg --block 24 --n_boot 2000
```
